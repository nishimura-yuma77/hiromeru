# Hiromeru LPの検索集客計画

2026-10-18 / v2 / 検討用

## 1. 検索から、どのような人に来てもらうか

採用にSNSを取り入れたいが、始め方がわからない中小企業に、Hiromeruを見つけてもらうことを目指します。対象は公開LPの1ページです。

Hiromeruは採用Xの企画と投稿づくりを支援するAIエージェントです。採用の悩みを相談すると、AIが必要な情報を質問し、施策案を作ります。利用者が施策を承認すると、AIが投稿案を作成します。利用者は内容を確認・修正して、公開を判断します。

初期登録は運営が担当し、利用開始後はAIとの対話で進められる形を目指します。検索から訪れた人が、この使い方と自分が行う作業を理解し、メールで導入を相談できるLPにします。

## 2. 狙う検索語と、その理由

主に狙う検索語の候補は「X 採用 AI」です。採用Xの企画や投稿を、AIに任せる方法・サービスを探している人を想定しています。

この語句は、用途、対応媒体、強みをまとめて表せます。ただし、検索需要の大きさや上位表示のしやすさは確認できていません。検索結果には採用活動の解説とAI面接など異なる用途のページが混在していたため、候補として扱い、公開後に実際の検索語を見て見直します。

| 語句 | 想定する疑問 | LPでの扱い |
| --- | --- | --- |
| X 採用 AI | 採用Xの企画や投稿をAIに任せられるか | 中心となる候補。相談、施策案、投稿案、確認・承認の流れを説明する |
| 採用 SNS AI / X 採用 運用 支援 | 採用目的のSNS運用を何で支援できるか | 現在はXに対応することと、任せられる仕事を説明する |
| 中小企業 SNS 採用 | 自社の体制でも取り組めるか | 専任者を置きにくい企業向けに、利用例と導入の流れを示す |
| SNS採用 始め方 / X 採用 始め方 | 最初に何を決めればよいか | 募集したい人材と採用課題を相談する例を、本文やFAQに入れる |
| SNS採用 運用代行 費用 | いくらで、どこまで任せられるか | 主な検索語としては保留。料金決定後に、含まれる仕事と利用者側の作業を示す |
| SNS採用 / 採用 AI | 採用活動全般や選考についても知りたい | 用途が広いため、単独で中心には据えない |
| Hiromeru / Hiromeru 採用 | サービスの詳細と相談先を知りたい | サービス名、提供内容、運営情報、相談先をわかりやすく掲載する |

2026-10-18に、日本語の検索ツールで「X 採用 AI」「中小企業 採用 SNS 始め方 X 採用 AI 運用」「X 採用 AI 運用 支援 ツール 2026」「SNS 採用 運用 代行 費用 中小企業」を調べました。

| 見られた情報 | HiromeruのLPで答えること |
| --- | --- |
| SNS採用の始め方を扱う解説では、媒体選び、投稿テーマ、運用体制、応募導線、計測が説明されていた | 一般的な手順の紹介に加え、相談から提案までを実際の利用イメージで示す |
| XのAI運用ツールでは、日本語による操作や投稿生成、自動配信が説明されていた | 採用課題の相談から企画を作る流れと、人が確認・承認するタイミングを示す |

## 3. LPで答える疑問

中心となるメッセージは「採用の悩みを話すところから。企画と投稿づくりは、AIにお任せ。」です。AIに任せられる仕事を先に伝え、相談例、人とAIの役割、利用開始、振り返り、料金の順に説明します。

| 読者の疑問 | LPで伝える内容 |
| --- | --- |
| 何を相談すればよいか | 募集したい人材や採用の悩みを伝えると、AIが必要な情報を質問して施策を考える |
| AIにどこまで任せられるか | 情報の確認と調査、施策立案、承認された施策に沿った投稿案作成、投稿結果の計測・記録を支援する |
| 自社は何をするか | 会社の情報を伝え、施策案と投稿案を確認・修正する。それぞれの段階で承認し、投稿を公開する |
| 初めてでも始められるか | 過去の投稿データがなくても、募集内容や採用課題の相談から始める使い方を示す。初心者の操作性は今後確認する |
| どう導入するか | 初期登録は運営が担当する。必要な情報、接続準備、利用開始までの期間は今後決める |
| 投稿の結果をどう見るか | 初週の閲覧数と応募ページへの流入ユーザー数を記録し、次の提案で使う。X・GA4の設定が必要で、応募・採用件数とは区別する |
| 費用はいくらか | 具体的な料金は今後決定する。月額、初期費用、利用上限、含まれる仕事と利用者側の作業を一緒に示す |

画像だけでなく本文のテキストでも対象と提供内容を伝え、図や画面には内容に合う代替テキストを付けます。タイトルや説明文は、検索結果にそのまま表示されるとは限りません。

## 4. 検索から読めるLPにする

公開時には、検索エンジンがLPを取得し、タイトルと主要な本文を読める状態かを確認します。以下は今後確認する項目です。

| 項目 | 確かめること |
| --- | --- |
| 公開先 | 正式なドメインとURLを決め、HTTPSで認証なしに本文を読め、正常な応答が返ることを確認する |
| 検索への公開設定 | 本番LPに、検索への掲載やクロールを意図せず止める設定がないか確認する。Preview環境とは区別する |
| 正規URL | 検索エンジンに示す正規URLを実際の公開先にそろえ、別ホストやURL表記の違いで内容が分散しないようにする |
| 本文とページ情報 | HTMLと表示結果にタイトル、説明文、主見出し、主要本文があり、実際のサービス内容と一致していることを確認する。認証画面への意図しない共通適用も確認する |
| 操作性 | モバイル・デスクトップとキーボードで、本文、利用例、相談先を確認し、メール相談やログインへ移動できることを確かめる |
| 表示性能 | 画像のサイズや読み込みによる表示の遅れ・ずれを調べ、改善項目を記録する |
| サイトマップ | 公開URLを掲載する場合は、正規URLとそろえる |
| 実装の確認 | Frontendのlint・buildなどを実行し、結果を記録する |

検索エンジンに読み取れる状態にすることと、インデックス登録や上位表示が実現することは別です。公開時の確認だけで、順位や流入数を保証するものではありません。

## 5. 公開後に見る指標

Google Search Consoleは現在未登録です。LP公開後に設定し、所有権とLPの取得・インデックス状況を確認します。正式ドメイン、設定担当者、設定日、確認日、記録先は今後決めます。

中心となる指標はGoogle検索結果からLPへのクリック数です。表示回数を補助情報とし、実際に表示された検索語と端末別の状況も確認します。検索パフォーマンスはLPのURLで絞り、検索タイプをウェブにして記録します。

初回は設定後4週間を目安に確認し、その後は月単位で比較する案です。期間とタイムゾーン、LPの変更日を記録し、データがない期間を0件と解釈しません。現在の順位、インデックス状況、クリック数は未調査です。

| 見えた状況 | 次に確かめること |
| --- | --- |
| インデックスされない | LPを取得できるか、公開設定と正規URLが適切か、本文を読み取れるか |
| 表示が少ない | 実際の検索語と本文が合っているか、関連する発信からリンクされているか |
| 表示されるがクリックされにくい | タイトル・説明と検索意図が合っているか。端末や掲載位置も確認する |
| 想定と違う語句で表示される | その疑問に答えられるサービスかを判断し、本文や狙う語句を見直す |
| 検索クリックはあるが相談が少ない | 相談内容の説明、ボタン、メールアプリの動作、宛先を確認する |

Google検索でのクリック数はページ閲覧数や相談メール数とは異なります。相談メールは初期段階では流入元を区別しないため、検索経由の相談率は算出しません。クリックが少ない場合も、検索需要がないとすぐに判断せず、表示状況と内容を合わせて見直します。
