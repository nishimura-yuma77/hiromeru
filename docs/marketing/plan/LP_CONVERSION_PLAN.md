# Hiromeru マーケティング・LP計画

2026-10-18 / v2 / 検討用

## 1. 誰に、何を提供するか

Hiromeruは採用にSNSを取り入れたいが、何から始めればよいかわからない中小企業のためのAIエージェントです。最初の対応媒体はXです。

採用の悩みを相談すると、AIが必要な情報を質問し、調査や施策立案、投稿案の作成を進めます。利用者は自社の情報を伝え、提案を確認・修正し、施策の確定と公開を判断します。

専任担当者を新たに雇うより低い費用で提供することを目指します。具体的な料金は今後決定します。顧客側にも情報提供や確認の作業があるため、費用を比較する際は、任せられる仕事と利用者が行う仕事を合わせて示します。

初期登録はHiromeru運営が担当します。利用開始後はAIとの対話で企画を進められる形を目指します。LPではこの使い方を伝えてメール相談につなげます。

### 想定する利用者

経営者や、採用を他の業務と兼務する担当者を想定しています。具体的な業種や企業規模、役職はまだ絞っていません。

| 困っている場面 | Hiromeruで得たい変化 |
| --- | --- |
| SNSで採用の発信をしたいが、何を投稿すればよいかわからない | 採用の悩みを相談し、AIの質問に答えながら企画を決められる |
| 企画や文章づくりに時間をかけにくい | AIが用意した案を確認し、自社に合う内容に仕上げられる |
| 専任者を雇う予算をかけにくい | 料金と任せられる仕事を見て、導入を判断できる |
| 投稿した後の振り返りまで手が回らない | 結果が記録され、次の相談で過去の施策や結果を使える |

これらは想定する利用場面であり、顧客の体験談ではありません。

### 中心となるユーザーストーリー

> 中小企業で採用を担う立場として、SNSで会社の魅力を伝えたい。しかし、何を発信すればよいかわからず、専任担当者を雇う余裕もない。募集したい人材と会社のことを伝えたら、AIに企画と投稿案の作成を進めてほしい。自分は提案を確認し、自社に合う内容に仕上げて発信したい。

## 2. LPで最も伝えたいこと

**採用の悩みを話すところから。企画と投稿づくりは、AIにお任せ。**

最初に伝えるのは、AIに任せられる仕事です。続いて、知識がなくても相談から始められる使い方と、人が確認するタイミングを見せます。過去の結果を次の提案に使う機能は、継続して利用する価値として紹介します。

初めて取り組む企業には過去の投稿データがないため、LPの冒頭では最初の相談から提案までを描きます。SNS初心者が実際に使い始められるかは、利用者による操作確認で確かめます。

### 訴求の比較

| 切り口 | 答える疑問 | 使い方と選ぶ理由 |
| --- | --- | --- |
| AIに企画・制作を任せられる | 誰が企画を考え、投稿を作るのか | 主訴求にする。質問、調査、施策立案、投稿案作成という仕事を、会話と提案画面で具体的に示せる |
| 初心者でも相談から始められる | 知識がなくても使えるか | 主訴求を支える説明にする。何を入力し、何を受け取るかを見せる。初心者の操作性は今後確かめる |
| 専任者の採用より費用を抑える | 人を雇う予算がなくても導入できるか | 料金決定後に具体化する。月額、初期費用、利用上限、利用者側の作業を示して比較できるようにする |

### 情報を伝える順序

相談例を先に見せる構成を推奨します。利用者が最初に何を行い、AIからどのような提案を受け取るかを想像しやすいと考えるためです。

| 構成案 | 順序 | 判断 |
| --- | --- | --- |
| 利用体験を先に見せる | 対象と価値 → 相談・質問・提案の例 → AIと人の役割 → 利用開始 → 計測と振り返り → 料金・FAQ → メール相談 | 推奨。始め方がわからない人への説明を優先する |
| 費用と体制を先に見せる | 専任者を置けない課題 → 料金と仕事の範囲 → AIと人の役割 → 利用例 → 利用開始・FAQ → メール相談 | 料金決定後の候補。費用を先に判断したい人に向く可能性がある |

## 3. LPの構成と文言案

以下は掲載原稿の案です。料金や導入条件など、決まっていない内容は確定後に反映します。

### ファーストビュー

肩書き: **中小企業のための、採用X支援AIエージェント**

見出し: **採用の悩みを話すところから。企画と投稿づくりは、AIにお任せ。**

> 何を発信すればよいかわからなくても、Hiromeruに相談できます。AIが募集内容や会社の特徴を質問し、施策とXの投稿案を用意。提案を確認・修正しながら、自社の発信を始められます。

相談ボタン: **採用Xの導入をメールで相談する**

ボタン付近の案内: **メールアプリが開きます。内容を確認して送信してください。**

### 相談から提案までの利用例

見出し: **募集したい人材と、採用の悩みを教えてください。**

会話例には「利用イメージ」と表示します。

> 担当者: 営業職を採用したいです。会社の雰囲気を伝える発信を始めたいのですが、何を投稿すればよいかわかりません。
>
> AI: 営業の仕事内容と、会社の雰囲気が伝わる具体的なエピソードを教えてください。

続けて、回答を踏まえた施策案と、その承認後に作る投稿案を見せます。施策案では誰に何を伝えるための取り組みかを具体的に示します。会社の特徴や待遇は利用者が伝えた情報を使います。

### AIと人の役割

見出し: **企画と投稿案はAIへ。内容を確かめて、公開を決める。**

> AIが施策案と投稿案を作成します。気になる点は、その場で書き換えることも、AIに修正を相談することもできます。Xへの投稿は、あなたが承認・公開ボタンを押したときに実行します。

| 段階 | AIが進めること | 利用者が行うこと |
| --- | --- | --- |
| 企画 | 必要な情報を質問し、関連情報を調べ、施策案を作る | 募集内容や会社の情報を伝え、施策案を確認・修正して承認する |
| 投稿づくり | 承認された施策に沿って投稿案を作り、修正の相談に応じる | 内容を確認・修正し、承認・公開ボタンで投稿する |
| 振り返り | 投稿結果を計測・記録し、次の相談で関連する情報を参照する | 次に取り組みたいことを相談する |

施策の承認と投稿の承認・公開は、それぞれの段階で行います。常時自律投稿や予約投稿は、現在説明する提供範囲に含めません。

### 利用開始までの流れ

見出し: **初期登録は運営が担当。利用開始後はAIに相談できます。**

> Hiromeru運営が初期登録を行います。利用開始後は、採用の悩みをAIに相談するところから始められます。

導入の流れは「メール相談 → 利用申し込み → 運営による初期登録 → AIとの対話で利用開始」を想定しています。相談から申し込みまでの手続き、初期登録に必要な情報、X・GA4の接続準備、利用開始までの期間は今後決めます。

初期登録にXアカウントの開設や採用ページの制作を含むかは決まっていません。企業ごとの接続設定やアカウントの案内を含め、複数の企業に提供するための導入手順も確認が必要です。

### 投稿後の振り返り

見出し: **投稿の結果を記録して、次の企画へ。**

> 公開後は初週の閲覧数と、投稿経由で応募ページを訪れたユーザー数を計測。施策や投稿と紐づけて記録し、次の提案で参照します。

計測にはX・GA4の接続と設定が必要です。結果は公開から7日経過後の日次処理で取得します。応募ページへの流入と、応募・採用の件数は区別します。

### 料金とよくある質問

料金は、月額、初期費用、利用上限、料金に含まれる仕事、利用者側の作業を一緒に示します。専任者の採用との費用比較は比較する仕事と期間をそろえたうえで行います。

| 質問 | 回答案 |
| --- | --- |
| SNSの知識がなくても相談できますか？ | 採用の悩みを相談すると、AIが必要な情報を質問し、施策案を作成します。 |
| AIが勝手に投稿することはありますか？ | Xへの投稿は、内容を確認し、承認・公開ボタンを押したときに実行します。 |
| どのSNSに対応していますか？ | 現在の対象はXです。 |
| 過去の投稿データがなくても始められますか？ | 募集内容や採用課題を相談するところから始めます。過去の施策や結果がある場合は、関連情報を参照します。 |
| 料金はいくらですか？ | 具体的な料金と適用条件は今後決定します。 |

### メール相談への案内

ボタンの文言は「採用Xの導入をメールで相談する」を推奨します。用途と相談内容、メールを使うことが伝わります。「Hiromeruについてメールで問い合わせる」も候補ですが、その場合は周囲に相談内容の説明を添えます。

案内文の候補は「導入の進め方や、AIに任せられる範囲についてご相談ください。」です。運営が対応できる範囲を決めてから掲載します。

メールアプリが開くことをボタン付近に示し、宛先も読めるようにします。件名の候補は「Hiromeruの導入相談」です。本文の入力例を用意する場合は、会社名、募集職種、相談したいことを任意で書ける形にします。

相談用メールアドレス、受付・返信の運用は未定です。無料相談の有無、返信時期、個別の企画提案、相談後の契約条件も、決定後に案内します。既存利用者には相談窓口とは別にログイン画面への導線を設けます。

## 4. 公開前に確かめること

過去の投稿データがない状態で、相談、AIの質問、施策の承認、投稿案の修正、承認・公開まで進められるかを確認します。各企業のX・GA4接続と計測も、提供する環境で確かめます。

LPは検索、X投稿、営業からの共有という訪問のきっかけごとに、冒頭で用途が伝わるかを確認します。モバイルとデスクトップで表示・操作を確かめ、メールアプリの起動、宛先表示、ログインへの移動も確認します。これらの画面・操作確認は未実施です。

## 5. 公開後に見る指標

| 指標 | 確認すること |
| --- | --- |
| 相談メール総数 | 対象期間に受信したHiromeruへの相談メール数。受信日時と相談の要旨を記録する |
| メール相談ボタンのクリック数 | ボタンが押された回数。設置位置を区別し、動作確認のクリックを別に記録する |

相談メールは、新しい相談を受けた最初のメールを数え、返信、迷惑メール、営業メールを除外する案です。クリックの計測方法と合わせて、公開前に集計ルール、担当者、記録先を決めます。初回は公開後4週間を目安に、週ごとの集計と期間全体の振り返りを行う案です。

メールの流入元は初期段階では区別しないため、他経路からの相談も総数に含まれます。ボタンのクリックは送信完了でも人数でもありません。LP訪問数やクリック数から、LP由来の相談率は算出しません。計測できなかった期間は「未計測」と記録します。

クリックが少ない場合は計測、用途説明、利用例、ボタンの見つけやすさを確認します。クリックがあるのにメールが少ない場合は、メールアプリの動作、宛先、入力の手間を確認します。相談内容が想定と異なる場合は、対応媒体や任せられる仕事の説明を見直します。相談が増減したときは、営業やX投稿など他の活動も含めて振り返ります。
